🏗 What We Built

SondelaBiz is a B2B network + public business directory for Mdantsane township, East London. Two products in one:

Part A — Public Directory (no login)

Anyone in South Africa can search for a Mdantsane business, see their Trusted Trader badge, rating, and services, and contact them instantly via WhatsApp. No app to install. Works on any phone.

Part B — B2B Network (login required)

Registered businesses can post "I NEED" and "I OFFER" requests on the board, respond to each other's posts, confirm trades, and build a verified reputation through the Trusted Trader system.

Trusted Trader System

⚙️ Local Setup (do this first)

⚠️
Everyone needs to clone the repo and run npm install. Only Lindokuhle needs to set up MySQL.

Step 1 — Clone the repo

git clone https://github.com/Nanda-Regine/SondelaBiz.git
cd SondelaBiz

Step 2 — Install dependencies

npm install

Step 3 — Create your .env file

cp .env.example .env

Then open .env and fill in your MySQL details:

PORT=3000
NODE_ENV=development
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_mysql_password_here
DB_NAME=sondela_biz
JWT_SECRET=make_up_any_long_random_string_here
JWT_EXPIRES_IN=7d
🚫
NEVER commit .env to GitHub. It's already in .gitignore — but double check. If you accidentally commit it, tell Lindokuhle immediately.

Step 4 — Set up MySQL database

mysql -u root -p < server/db/schema.sql

This creates the sondela_biz database and all 9 tables.

Step 5 — Seed demo data

npm run seed

Creates 6 demo Mdantsane businesses + board posts. Demo password for all: sondela123

Step 6 — Start the server

npm run dev

Open http://localhost:3000 — you should see the homepage.

Step 7 — Switch off DEMO_MODE

In public/js/app.js, line 5, change:

window.DEMO_MODE = true   // ← change to false

Now the pages use real API data instead of mock data.

💡
Can't set up MySQL right now? No problem — open any HTML file directly in your browser. Everything works with DEMO_MODE=true. Build the UI first, wire the API later.

🌿 Git Workflow

🚫
Never push directly to main. Always create your own branch, push it, and ask someone to review before merging.

Daily git flow — do this every time

1
Pull latest changes first
git pull origin main
2
Create your branch
git checkout -b feature/xolani-mobile-nav
Use your name + what you're doing
3
Make your changes. Save. Test in browser.
4
Add and commit
git add .
git commit -m "feat: add mobile hamburger menu"
5
Push your branch
git push origin feature/xolani-mobile-nav
6
Go to GitHub → open a Pull Request → ask Lindokuhle to merge it

Good commit message examples

feat: add search filter to directory page
feat: wire register form to /api/auth/register
fix: mobile layout breaks on iPhone 12
fix: board posts not showing after refresh
style: improve button hover states
docs: update README setup instructions

What if you get a merge conflict?

1
git pull origin main — pull the latest
2
Open the conflicting file — look for <<<<<<< and >>>>>>> markers
3
Keep the code you want, delete the conflict markers, save
4
git add . then git commit -m "fix: resolve merge conflict"

📡 API Reference

💡
All endpoints are at http://localhost:3000/api/... when running locally. Send Authorization: Bearer YOUR_TOKEN header for protected routes.

Auth

MethodEndpointBodyReturns
POST/api/auth/registername, category, zone, whatsapp, password{ token, business }
POST/api/auth/loginwhatsapp, password{ token, business }

Businesses

MethodEndpointAuth?Notes
GET/api/businessesNoQuery: q, category, zone, limit, offset
GET/api/businesses/:idNoIncludes offers, needs, reviews
GET/api/businesses/me/profile✅ YesYour own full profile
POST/api/businesses/review/:id✅ YesBody: rating (1–5), comment, transactionId

Board

MethodEndpointAuth?Notes
GET/api/boardNoQuery: type=need|offer, limit, offset
POST/api/board✅ YesBody: type, title, description, budget, isUrgent
POST/api/board/:id/respond✅ YesBody: message. Auto-creates a transaction.
GET/api/board/transactions✅ YesAll your trades (sent + received)
PATCH/api/board/transactions/:id✅ YesBody: status (pending/agreed/complete/cancelled)

How to test with curl

# Register a new business
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name":"My Salon","category":"salon","zone":"Unit 4","whatsapp":"27700000001","password":"test1234"}'

# Login
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"whatsapp":"27641234567","password":"sondela123"}'

# Get all businesses
curl http://localhost:3000/api/businesses

# Search for plumbers
curl "http://localhost:3000/api/businesses?category=plumber"

🗄 Database Tables

TablePurposeKey columns
businessesCore business profiles + authid, name, category, zone, whatsapp, password_hash, trader_tier, rating, completed_deals
usersAuth accounts (linked to businesses)id, business_id, role
categoriesCategory lookup (pre-seeded, 8 rows)id, slug, name, icon, color
offersServices each business providesid, business_id, offer_text
requestsThings each business needs to sourceid, business_id, title
board_postsPublic I NEED / I OFFER boardid, business_id, type, title, budget, is_urgent, response_count
board_responsesReplies to board postsid, post_id, business_id, message
transactionsTrade records (pending → complete)id, post_id, from_business_id, to_business_id, status, amount
reviewsRatings that auto-update tierid, business_id, author_business_id, rating, comment
⚡
MySQL trigger magic: Every time a review is inserted, a trigger automatically recalculates the average rating and updates the trader_tier. You don't need to write any code for this — the database handles it.

Soft-delete rule

We never hard-delete records. Every important table has a deleted_at column. To "delete" something:

UPDATE board_posts SET deleted_at = NOW() WHERE id = ?;

To query only active records, always filter: WHERE deleted_at IS NULL

💡 Tips & Tricks for the Hackathon

General

🏆
Working beats perfect. A page that works at 80% is worth 10x more than a perfect page that isn't finished. Ship it, then polish it.
🔄
Commit often. Every 30 minutes, git add . && git commit -m "WIP: ...". You can always clean it up later. You can't recover code you lost.
📱
Test on your actual phone. Open Chrome Dev Tools → toggle device toolbar → select "iPhone 12" or "Galaxy S20". But also send the link to your phone and click around.
🎯
Demo mode first. Make sure DEMO_MODE=true works perfectly before switching to the real API. Judges don't care if it's mock data — they care if it works.

CSS tips

🎨
Use the design tokens. Don't type #E040FB — use var(--fuchsia). All colours, spacing, and border-radius are already defined in css/main.css.
📦
Reuse classes. .glass, .btn btn-primary, .badge badge-fuchsia, .biz-card — these are all ready. Don't reinvent them.

JavaScript tips

🔧
Use window.toast(). For any user feedback, call window.toast('Your message here'). It's already wired up in app.js.
📡
Real API calls. Use the Businesses, Board, and Auth objects from api.js. Example: const data = await Businesses.list({category:'salon'})

For the presentation

🎤
Tell the story first. "A plumber in Mdantsane has no website, no Google listing, no way for a Sandton contractor to find them. SondelaBiz fixes that." — THEN show the demo.
⏱
Practice the demo script out loud. 3 minutes feels long until you're in front of judges. Rehearse it twice as a team before the competition.
📊
Lead with impact numbers. "170,000 people. R2-billion economy. Zero platforms serving them." Say the numbers first, show the product second.

🔴 Common Errors & Fixes

ErrorFix
Cannot connect to MySQL Check your .env file — is DB_PASSWORD correct? Is MySQL running? Run mysql -u root -p to test.
JWT_SECRET is not defined Your .env file is missing or not loaded. Make sure it's in the project root, not inside server/.
Table doesn't exist Run the schema again: mysql -u root -p sondela_biz < server/db/schema.sql
npm run dev: nodemon not found Run npm install first.
Page is blank / white screen Open browser Console (F12). Check for red errors. Usually a missing file path or JS syntax error.
window.renderBizCard is not a function app.js hasn't loaded yet. Make sure <script src="js/app.js" type="module"> is in the <body> before your inline scripts.
CORS error in browser console Your API call is going to the wrong URL. Check that BASE = '/api' in api.js (not localhost:3000/api).
Git: "rejected — non-fast-forward" Someone else pushed to main. Pull first: git pull origin main, fix conflicts, then push again.
Vercel build failed Check the Vercel dashboard for the error log. Usually a missing file. Push a fix commit to main and Vercel auto-redeploys.
CSS changes not showing Hard reload: Ctrl+Shift+R (Windows) or Cmd+Shift+R (Mac). Browser may be caching old CSS.

⚠️ Hard Rules — No Exceptions

🚫
Rule 1: NEVER touch, modify, or commit the .env or .env.local files. Ever. On any project.
🚫
Rule 2: NEVER expose passwords, tokens, or API keys in client-side code (HTML, CSS, JS). These go in .env only.
🚫
Rule 3: NEVER hard-delete database records. Always use soft-delete: UPDATE table SET deleted_at = NOW() WHERE id = ?
🚫
Rule 4: NEVER commit directly to main. Always use a branch. Always.
✅
When in doubt, ask Lindokuhle. They are the team lead and have the full context of the codebase.
